## 写作规范

- 简洁直接，删除重复铺垫，保留技术结论、适用条件与操作步骤。
- 以当前工作区为基线，用 [sources.repos](../../sources.repos) 固定版本；记录相关仓库的提交与本地修改，未知信息明确标注。
- 源码引用注明仓库、路径、类或函数及提交号；行号辅助定位。
- 区分源码事实、设计解释和实验观察。未运行的实验标为待验证，预期输出不作为实测。
- 调用链注明跨进程、进程内、借用消息和 RMW 实现等条件。
- 只摘录必要代码并附来源，以解释和图示为主体。

每章包含问题、示例、对象关系、调用链、源码分析、实验、边界条件和小结。书稿使用 Markdown，图示优先使用文本源；实验步骤放在所属章节，代码保存在 `experiments/`。
